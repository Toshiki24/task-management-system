## 2. システム概要

### 2.1 システム名称

**Task Management System**

### 2.2 概要

プロジェクト単位でタスクを管理するWebアプリケーション。

ユーザーはプロジェクトを作成し、プロジェクトメンバーに対してタスクを割り当てることができる。

タスクには、担当者・ステータス・優先度・期限などを設定でき、コメントやステータス変更履歴を管理することで、プロジェクトの進捗状況を把握できるようにする。

### 2.3 システム構成

本システムは、フロントエンドとバックエンドを分離したWebアプリケーションとして構築する。

```text
[Browser]
    |
    | HTTPS
    v
[Next.js / TypeScript]
    |
    | REST API / HTTPS
    v
[ASP.NET Core Web API]
    |
    | Entity Framework Core / LINQ
    v
[PostgreSQL]
```

本番環境ではAWSを利用する。

## 3. 背景・目的

### 3.1 背景

ソフトウェア開発では、プロジェクトごとに複数のタスクを管理し、担当者・期限・進捗状況などを把握する必要がある。

本システムでは、実際の開発現場で利用されるタスク管理システムを想定し、Webアプリケーションとして必要となる基本的な機能を実装する。

### 3.2 目的

本システムの開発を通じて、以下の開発工程を一通り経験することを目的とする。

* 要件定義
* 基本設計
* データベース設計
* API設計
* 画面設計
* フロントエンド開発
* バックエンド開発
* データベース開発
* テスト
* AWSへのデプロイ
* GitHubによるソースコード・ドキュメント管理

また、以下の技術を組み合わせたWebアプリケーション開発経験を示すことを目的とする。

* Next.js
* TypeScript
* React
* C#
* ASP.NET Core Web API
* Entity Framework Core
* LINQ
* PostgreSQL
* AWS

# 7. 機能要件

## 7.1 認証機能

### 概要

ユーザーがシステムへログインし、認証済みユーザーのみがシステムを利用できるようにする。

### 要件

* ログイン
* ログアウト
* 認証状態の確認
* 未認証ユーザーによる保護対象画面へのアクセス制御

---

## 7.2 ユーザー管理機能

### 概要

システムを利用するユーザーを管理する。

### 要件

* ユーザー登録
* ユーザー一覧表示
* ユーザー詳細表示
* ユーザー情報編集
* ユーザーの有効・無効管理

---

## 7.3 プロジェクト管理機能

### 概要

開発プロジェクトを登録・管理する。

### 要件

* プロジェクト作成
* プロジェクト一覧表示
* プロジェクト詳細表示
* プロジェクト編集
* プロジェクト削除
* プロジェクト開始日設定
* プロジェクト終了日設定
* プロジェクトステータス管理

### プロジェクトステータス

初期値として以下を想定する。

* ACTIVE
* COMPLETED
* ARCHIVED

---

## 7.4 プロジェクトメンバー管理機能

### 概要

プロジェクトに参加するユーザーを管理する。

### 要件

* プロジェクトへのメンバー追加
* プロジェクトからのメンバー削除
* メンバー一覧表示
* プロジェクト内のロール設定

### ロール

初期値として以下を想定する。

* OWNER
* MEMBER

---

## 7.5 タスク管理機能

### 概要

プロジェクトに紐づくタスクを管理する。

### 要件

* タスク作成
* タスク一覧表示
* タスク詳細表示
* タスク編集
* タスク削除
* 担当者設定
* ステータス設定
* 優先度設定
* 期限設定

### タスクステータス

```text
TODO
IN_PROGRESS
DONE
```

### タスク優先度

```text
LOW
MEDIUM
HIGH
```

---

## 7.6 タスクコメント機能

### 概要

タスクに対してコメントを登録し、タスクに関する情報を共有できるようにする。

### 要件

* コメント登録
* コメント一覧表示
* コメント削除
* コメント投稿者の表示
* コメント投稿日時の表示

---

## 7.7 タスクステータス履歴機能

### 概要

タスクのステータス変更履歴を保存する。

### 例

```text
TODO
 ↓
IN_PROGRESS
 ↓
DONE
```

### 保存する情報

* タスクID
* 変更ユーザー
* 変更前ステータス
* 変更後ステータス
* 変更日時

---

## 7.8 ダッシュボード機能

### 概要

プロジェクトおよびタスクの進捗状況を一覧で確認できるようにする。

### 表示項目

* プロジェクト数
* タスク総数
* TODO件数
* IN_PROGRESS件数
* DONE件数
* 期限超過タスク数
* 担当タスク数

---

## 7.9 タスク検索・絞り込み機能

### 概要

登録されたタスクを条件によって検索・絞り込みできるようにする。

### 検索条件

* タスクタイトル
* ステータス
* 優先度
* 担当者
* 期限
* プロジェクト

※初期開発では優先度を下げ、基本機能完成後に実装する。

---

# 8. 非機能要件

## 8.1 性能

* 一覧画面では必要なデータのみ取得する。
* データ量増加を考慮し、ページングを導入可能な設計とする。
* データベースへの不要なアクセスを抑制する。
* APIレスポンスを適切に制御する。

---

## 8.2 可用性

* 本番環境はAWS上に構築する。
* フロントエンドとバックエンドを分離する。
* APIとデータベースを適切に分離する。

---

## 8.3 保守性

* フロントエンドとバックエンドを分離する。
* REST APIを採用する。
* Entity Framework Coreを利用してデータアクセスを行う。
* LINQを利用してデータ検索・絞り込みを行う。
* GitHubでソースコードを管理する。
* GitHubで設計書・仕様書を管理する。
* 機能単位でコミットを行う。

---

## 8.4 拡張性

将来的に以下の機能を追加できる構成とする。

* タスク検索機能の強化
* ファイル添付
* メール通知
* Slack通知
* カレンダー表示
* AIによるタスク分類
* 外部サービス連携

---

## 8.5 可読性

* 命名規則を統一する。
* APIのレスポンス形式を統一する。
* エラーレスポンス形式を統一する。
* ソースコードに必要以上の複雑な処理を記述しない。

---

# 14. セキュリティ要件

以下のセキュリティ対策を実施する。

* HTTPSによる通信
* パスワードのハッシュ化
* 認証済みユーザーのみ保護対象APIへアクセス可能とする
* ロールに応じた認可を行う
* APIの入力値をバリデーションする
* SQLインジェクション対策を行う
* ORMを利用した安全なデータアクセスを行う
* 秘密情報をソースコードへ直接記述しない
* AWSの認証情報をGitHubへコミットしない
* 環境変数等を利用して環境ごとの設定を分離する
