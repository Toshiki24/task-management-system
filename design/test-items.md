## 2. テスト方針

基本設計書 §25 に基づき、以下6種類のテストを実施する。

| 分類     | 対象               | 本書での章 | 自動テストの実装先 |
| ------ | ---------------- | ----- | ------------------ |
| 単体テスト  | Service等の個別ロジック  | 4     | `backend/tests/TaskManagementSystem.Api.Tests`（xUnit） |
| APIテスト | APIのリクエスト・レスポンス  | 5     | `e2e/tests/api`（Playwright） |
| 結合テスト  | APIとDBの連携        | 6     | `e2e/tests/integration`（Playwright） |
| 画面テスト  | 画面操作およびAPI連携     | 7     | `e2e/tests/screen`（Playwright） |
| システムテスト | ログイン〜プロジェクト〜タスク管理の一連操作 | 8 | `e2e/tests/system`（Playwright） |
| セキュリティテスト | セキュリティ見直し記録（`security-review.md`）の課題に対する対策 | 9 | `e2e/tests/security`（Playwright） |

全項目を自動テストとして実装している。各テストの名前は本書のNo.（`UT-101`、`SCR-005-03` 等）で始まり、本書の項目と1対1で対応する。

## 3. 記入方法

各テスト項目について、実施後に以下を記入する。1回目の結果は残したまま、NG項目の修正後に行う再テストの結果を2回目の欄に記入する。

| 列       | 記入内容                                  |
| ------- | ------------------------------------- |
| 1回目結果   | 1回目の実施結果として `OK` または `NG` を記入する     |
| 1回目NG内容 | 1回目結果が`NG`の場合、実際の挙動・エラー内容を記載する       |
| 修正内容    | 1回目結果が`NG`の場合、原因および実施した修正内容を記載する（未修正なら「対応中」等） |
| 2回目結果   | 2回目（再テスト）の実施結果として `OK` または `NG` を記入する |
| 2回目NG内容 | 2回目結果が`NG`の場合、実際の挙動・エラー内容を記載する       |

テスト方法（手順）に記載のコマンド例は、ローカル開発環境（`docker compose up -d` でDB起動、バックエンドは `http://localhost:5000`、フロントエンドは `http://localhost:3000`）を前提とする。
